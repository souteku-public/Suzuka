## 1. 前提と記号の定義

### システム構成

```
                  雲台（pan/tilt 制御可能）
                 ┌─────────────────────────┐
                 │                         │
          ┌──────┤                         ├──────┐
          │cam1  │      回転軸             │ cam2 │
          │物体  │       ↑                 │ RGB  │
          │認識用│       │                 │カメラ │
          └──────┘       │                 └──────┘
                         │
                    ━━━━━┿━━━━━ 三脚
```

- **カメラ1 (cam1)**: 物体認識用カメラ（低解像度、例: 640×480）
- **カメラ2 (cam2)**: RGBカメラ（高解像度、例: 1920×1080）
- 2台は同一の雲台に固定されており、雲台が回転すると両方が同時に動く

### 記号一覧

| 記号 | 意味 | 次元 |
|------|------|------|
| K₁, K₂ | カメラ1, 2 の内部パラメータ行列 | 3×3 |
| R | 回転行列 | 3×3 |
| t | 並進ベクトル | 3×1 |
| H | Homography 行列 | 3×3 |
| p | ピクセル座標（同次座標） | 3×1 |
| fx, fy | 焦点距離（ピクセル単位） | スカラー |
| cx, cy | 主点（光学中心のピクセル座標） | スカラー |
| n | 平面の法線ベクトル | 3×1 |
| d | カメラから平面までの距離 | スカラー |

## 2. ピンホールカメラモデル

### 2.1 3D点からピクセル座標への投影

3D空間の点 P = (X, Y, Z)ᵀ がカメラの画像上のどこに映るかは、
以下の式で表される:

```
       ┌ u ┐       ┌ fx  0  cx ┐   ┌ X ┐
  s  · │ v │   =   │  0  fy cy │ · │ Y │
       └ 1 ┘       └  0   0  1 ┘   └ Z ┘

  s · p  =  K · P_cam
```

ここで:
- **(u, v)** はピクセル座標
- **s** はスケールファクター（Z座標に相当）
- **K** は内部パラメータ行列
- **P_cam** はカメラ座標系での3D点

### 2.2 内部パラメータ行列 K の意味

```
       ┌ fx   0  cx ┐
  K =  │  0  fy  cy │
       └  0   0   1 ┘
```

| パラメータ | 物理的意味 |
|-----------|-----------|
| fx, fy | 焦点距離をピクセル単位で表したもの。f (mm) × (ピクセル密度 px/mm) |
| cx, cy | 光学軸が画像平面と交わる点（主点）。通常は画像中心付近 |

**重要**: K はカメラ固有の値であり、カメラを動かしても変化しない。
ズームしない限り一定である。

### 2.3 ワールド座標からカメラ座標への変換

ワールド座標系の点 P_w をカメラ座標系に変換するには:

```
  P_cam = R · P_w + t
```

- **R** (3×3): カメラの姿勢を表す回転行列
- **t** (3×1): カメラの位置を表す並進ベクトル

よって、投影の全体式は:

```
  s · p = K · [R | t] · P_w（同次座標）
```

## 3. 2台のカメラ間の Homography

### 3.1 Homography とは

Homography とは、2つの画像間のピクセル座標の対応関係を表す
3×3 の射影変換行列である:

```
  s · p₂ = H · p₁
```

カメラ1上の点 p₁ = (u₁, v₁, 1)ᵀ に対応するカメラ2上の点
p₂ = (u₂, v₂, 1)ᵀ は、H を掛けて同次座標を正規化すれば得られる:

```
       H₁₁·u₁ + H₁₂·v₁ + H₁₃
  u₂ = ─────────────────────────
       H₃₁·u₁ + H₃₂·v₁ + H₃₃

       H₂₁·u₁ + H₂₂·v₁ + H₂₃
  v₂ = ─────────────────────────
       H₃₁·u₁ + H₃₂·v₁ + H₃₃
```

### 3.2 Homography が成立する2つの条件

Homography による2画像間の対応が成立するのは、以下の**いずれか**が
満たされる場合に限る:

#### 条件A: 被写体が平面上にある場合

3D空間内の点が1つの平面 π 上にある場合、その平面の法線を n、
カメラ1から平面までの距離を d とすると:

```
  H = K₂ · (R + t · nᵀ / d) · K₁⁻¹
```

ここで R, t はカメラ1からカメラ2への相対的な回転と並進。

**導出**:

平面上の点は nᵀ · P = d を満たす（P はカメラ1座標系）。
よって nᵀP/d = 1 が成り立つ。

カメラ1座標系の点 P をカメラ2座標系に変換すると:

```
  P₂ = R · P + t
     = R · P + t · 1
     = R · P + t · (nᵀP / d)
     = (R + t·nᵀ/d) · P
```

これをカメラ2に投影すると:

```
  s · p₂ = K₂ · P₂ = K₂ · (R + t·nᵀ/d) · P
```

一方、P = K₁⁻¹ · p₁ · s₁ であるから:

```
  s₂ · p₂ = K₂ · (R + t·nᵀ/d) · K₁⁻¹ · s₁ · p₁
```

スケールを吸収して:

```
  p₂ ∝ K₂ · (R + t·nᵀ/d) · K₁⁻¹ · p₁
```

よって **H = K₂ · (R + t·nᵀ/d) · K₁⁻¹**

#### 条件B: カメラが純回転のみの場合（t = 0）

2台のカメラの光学中心が同一点にある（あるいは並進が無視できる）場合:

```
  H = K₂ · R · K₁⁻¹
```

t·nᵀ/d の項が消えるため、被写体の形状や距離に依存しなくなる。

### 3.3 本システムへの適用

2台のカメラは雲台上に近接して設置されている。
被写体が十分遠方にある場合（d が大きい場合）:

```
  ‖t · nᵀ / d‖ → 0
```

よって:

```
  H ≈ K₂ · R_rel · K₁⁻¹
```

ここで R_rel はカメラ1からカメラ2への相対回転。

**4点で求めた Homography H_base には、K₁, K₂, R_rel の情報がすべて
含まれている。** これが以降の理論の出発点となる。

## 4. 雲台回転による Homography の変化

### 4.1 雲台回転の数学的表現

雲台が pan 方向（水平）に α 度、tilt 方向（垂直）に β 度
回転した場合、3D空間では以下の回転行列で表される:

**Y軸周りの回転（pan）**:
```
              ┌  cos α   0   sin α ┐
  R_y(α)  =  │    0     1     0   │
              └ -sin α   0   cos α ┘
```

**X軸周りの回転（tilt）**:
```
              ┌  1     0       0   ┐
  R_x(β)  =  │  0   cos β  -sin β │
              └  0   sin β   cos β ┘
```

**合成回転**:
```
  R_pantilt(α, β) = R_y(α) · R_x(β)
```

回転の適用順序は「先に tilt → 次に pan」。
これは雲台の物理的な動作（tilt軸がpan軸に載っている構造）に対応する。

### 4.2 雲台回転後の Homography の導出

#### 前提

- 基準角度 (pan₀, tilt₀) での Homography を H_base とする
- 雲台が (pan, tilt) に移動した
- 角度の変化量: Δpan = pan - pan₀, Δtilt = tilt - tilt₀

#### 導出

基準角度での Homography は:

```
  H_base = K₂ · R_rel · K₁⁻¹        ... (1)
```

雲台が R_pantilt だけ回転すると、両カメラが同時に回転する。
カメラ2から見た世界は R_pantilt だけ逆方向に回転したように見える。

重要なのは、**カメラ1の画像上の点は変化しない**ということ。
なぜなら:
- 物体認識カメラ（cam1）で検出した座標は、cam1の画像座標系での値
- 雲台が回転しても、cam1 に映る物体の位置は（物体が追従して映っている限り）
  cam1の画像座標として不変
- 変化するのは cam2（RGB）の画像上で対応する位置

カメラ2から見ると、雲台の回転により画像全体が回転移動する。
この回転は cam2 の画像座標系では:

```
  p₂_new = K₂ · R_pantilt · K₂⁻¹ · p₂_old
```

と表現される（後述の §4.3 で詳しく説明）。

よって、基準角度での対応 p₂ = H_base · p₁ に対して:

```
  p₂_new = K₂ · R_pantilt · K₂⁻¹ · H_base · p₁
```

すなわち:

```
  ┌─────────────────────────────────────────────────────────┐
  │                                                         │
  │  H(pan, tilt) = K₂ · R_pantilt(Δpan, Δtilt) · K₂⁻¹ · H_base  │
  │                                                         │
  │  ここで R_pantilt = R_y(Δpan) · R_x(Δtilt)             │
  │                                                         │
  └─────────────────────────────────────────────────────────┘
```

**これが本システムの核心的な公式である。**

### 4.3 K₂ · R · K₂⁻¹ の幾何学的意味

この変換の意味を分解して理解する:

```
  ステップ1: K₂⁻¹ · p₂
    → ピクセル座標 (u, v) を正規化画像座標に変換
    → カメラの焦点距離や主点の影響を除去
    → 方向ベクトル（3Dの視線方向）に変換

  ステップ2: R · (K₂⁻¹ · p₂)
    → 3D 空間で視線方向を回転
    → 雲台の回転に対応

  ステップ3: K₂ · R · (K₂⁻¹ · p₂)
    → 回転後の視線方向を再度ピクセル座標に投影
    → 回転後のカメラで見える位置を計算
```

つまり **K₂⁻¹ で3D空間に戻し → 回転し → K₂ でピクセルに戻す** という操作。
K₂ を正しく知っていれば、この変換は厳密に正しい。

### 4.4 具体的な計算例

カメラ2 の内部パラメータ:
```
       ┌ 1200    0   960 ┐
  K₂ = │    0  1200  540 │
       └    0     0    1 ┘
```

雲台が tilt 方向に +3° 回転した場合:

```
  Δtilt = 3°, Δpan = 0°

              ┌ 1      0       0    ┐
  R_x(3°) =  │ 0   0.9986  -0.0523 │
              └ 0   0.0523   0.9986 ┘

                          ┌ 1      0       0    ┐
  K₂ · R_x(3°) · K₂⁻¹ = │ 0   0.9986  -0.0523 │ （正規化座標空間での回転）
                          └ 0   0.0523   0.9986 ┘

  → ピクセル空間では約 62.8 ピクセルの垂直シフトに相当
    （1200 × sin(3°) ≈ 62.8）
```

## 5. K₂ の推定方法

### 5.1 なぜ K₂ の推定が必要か

公式 H(θ) = K₂ · R(Δθ) · K₂⁻¹ · H_base を使うには K₂ が必要だが、
通常 K₂ は未知である（カメラのスペックシートに焦点距離が書いてあっても、
ピクセル単位の正確な値は不明）。

しかし、**複数の雲台角度でキャリブレーションデータがあれば、
K₂ を逆算できる。**

### 5.2 推定の原理

角度 θ₁ でのキャリブレーション結果 H₁ が得られているとする。
基準角度での H_base と θ₁ での理論的な H₁ の関係は:

```
  H₁ = K₂ · R(Δθ₁) · K₂⁻¹ · H_base
```

ここで R(Δθ₁) は既知（雲台の角度から計算可能）、H_base と H₁ は
実測値。よって未知数は K₂ のみ。

K₂ は正方ピクセルを仮定すれば fx = fy で、主点は画像中心と仮定すると:

```
       ┌ fx   0   W/2 ┐
  K₂ = │  0  fx   H/2 │    （未知数は fx の1つだけ）
       └  0   0    1  ┘
```

### 5.3 推定アルゴリズム

実装では、fx を探索パラメータとして最適化する:

```
  1. fx の候補値を設定
  2. K₂(fx) を構成
  3. 各キャリブレーション角度 θᵢ に対して:
     a. H_predicted = K₂ · R(Δθᵢ) · K₂⁻¹ · H_base を計算
     b. 実測の対応点 (pts1, pts2) に対して再投影誤差を計算:
        error = Σ ‖ H_predicted · pts1ⱼ - pts2ⱼ ‖²
  4. 誤差が最小になる fx を採用
```

探索は2段階:
- **粗い探索**: fx を 0.3W 〜 2.0W の範囲で50点サンプリング
- **細かい探索**: 粗い探索の最良値の ±10% を100点サンプリング

### 5.4 キャリブレーション角度の数と精度

| キャリブレーション角度数 | K₂ 推定精度 | 備考 |
|---|---|---|
| 1 (基準のみ) | 推定不可 | 方程式が足りない |
| 2 (基準 + 1角度) | 推定可能 | 1軸の回転情報のみ |
| 3 (基準 + 上 + 右) | 良好 | 2軸の回転情報で fx を安定推定 |
| 5 (基準 + 上下左右) | 最良 | 冗長な拘束条件で精度向上 |

3角度以上あると、fx の推定が冗長になり（over-determined）、
ノイズに対するロバスト性が向上する。

## 6. 精度の理論的分析

### 6.1 誤差の分類

解析的手法の誤差は以下の3つに分類される:

#### 誤差源1: 純回転近似の誤差

```
  H_true = K₂ · (R + t·nᵀ/d) · K₁⁻¹
  H_approx = K₂ · R · K₁⁻¹
```

近似誤差は t·nᵀ/d の大きさに依存:

```
  相対誤差 ≈ ‖t‖ / d
```

| カメラ間距離 ‖t‖ | 被写体距離 d | 相対誤差 |
|---|---|---|
| 50mm | 2m | 2.5% |
| 50mm | 5m | 1.0% |
| 50mm | 10m | 0.5% |
| 50mm | 50m | 0.1% |

被写体が遠方であるほど近似精度は向上する。

#### 誤差源2: K₂ の推定誤差

K₂ の推定誤差 δfx があると、回転の画像座標への変換に誤差が生じる:

```
  ピクセル誤差 ≈ δfx · sin(Δθ)
```

例: δfx = 0.4 px（実測値）、Δθ = 5° の場合:
```
  誤差 ≈ 0.4 × sin(5°) ≈ 0.035 px
```

これは実測結果（0.03〜0.04 px）と一致する。

#### 誤差源3: H_base の推定誤差（4点の指定精度）

4点の手動指定には必ず誤差がある。この誤差は H_base に含まれ、
すべての角度の推定に伝播する。ただし:

- H_base の誤差は全角度に均等に影響する（特定角度で悪化しない）
- 4点を画像の広い範囲に分散配置することで緩和できる

### 6.2 誤差の角度依存性

解析的手法の誤差は角度に対してほぼ線形に増加する:

```
  ε(Δθ) ≈ δfx · sin(Δθ) ≈ δfx · Δθ  （小角度近似）
```

実測値:

| Δθ | 理論誤差 (δfx=0.4) | 実測平均誤差 |
|---|---|---|
| 1° | 0.007 px | 0.007 px |
| 3° | 0.021 px | 0.021 px |
| 5° | 0.035 px | 0.034 px |
| 7° | 0.049 px | 0.048 px |

**理論値と実測値がほぼ完全に一致している。**

### 6.3 CG 描画精度への影響

1920×1080 の RGB カメラにおける誤差の意味:

| 誤差 (px) | 画面比率 | 視認性 | 判定 |
|---|---|---|---|
| 0.05 px | 0.003% | 認識不可能 | 問題なし |
| 0.5 px | 0.026% | サブピクセル | 問題なし |
| 1 px | 0.052% | 境界で微かに見える | ほぼ問題なし |
| 5 px | 0.26% | はっきり見える | 要改善 |
| 20 px | 1.04% | 明らかにずれている | CG合成不可 |

解析的手法は最悪でも 0.08 px 程度なので、CG合成品質として十分。

## 7. IDW 補間が失敗する数学的理由

### 7.1 射影変換群 PGL(3) の非線形性

Homography は射影変換群 PGL(3) に属する。この群は:

- **リー群**であり、ユークリッド空間ではない
- 行列の線形結合は群の元とは限らない
- 「2つの Homography の平均」は数学的に意味をなさない

具体例:

```
  H₁ = ┌ 1  0  0 ┐    H₂ = ┌ 0 -1  0 ┐
       │ 0  1  0 │         │ 1  0  0 │   （90°回転）
       └ 0  0  1 ┘         └ 0  0  1 ┘

  (H₁ + H₂) / 2 = ┌ 0.5 -0.5  0 ┐
                    │ 0.5  0.5  0 │   ← det = 0.5 ≠ 1
                    └  0    0   1 ┘       45°回転 + 縮小
```

平均すると **回転だけでなくスケール変化が混入** する。
これが IDW 補間の根本的な問題。

### 7.2 IDW 補間の誤差の定量評価

3つのキャリブレーション点 (tilt = -5°, 0°, +5°) がある場合、
tilt = 2.5° での IDW 補間:

```
  距離: d₋₅ = 7.5, d₀ = 2.5, d₊₅ = 2.5

  重み: w₋₅ = 1/7.5 = 0.133
        w₀  = 1/2.5 = 0.400
        w₊₅ = 1/2.5 = 0.400

  H_idw = 0.133·H₋₅ + 0.400·H₀ + 0.400·H₊₅
```

この加重平均で生じる誤差の主因:

1. **射影成分の非線形混合**: H[2,0], H[2,1] の誤差が分母に入り、
   変換結果を非線形に歪める
2. **回転の非可換性**: R(α) + R(β) ≠ R(α+β) であるため、
   回転成分が正しく補間されない
3. **距離依存の重み歪み**: IDW の重みは角度距離に基づくが、
   Homography の変化量は角度に対して非線形

### 7.3 対角方向で誤差が特に大きい理由

pan=3°, tilt=3° のような対角方向では:

```
  R_true = R_y(3°) · R_x(3°)    ← 2軸の合成回転（非可換）
```

IDW はこれを各キャリブレーション点の Homography の重み付き和で
近似するが:

```
  R_y(3°) · R_x(3°) ≠ 加重平均(R_y(0)·R_x(5°), R_y(5°)·R_x(0°), ...)
```

**回転の非可換性** (R_y · R_x ≠ R_x · R_y) が直撃するため、
単軸方向よりも誤差が顕著に増大する。

## 8. 前提条件と限界

### 8.1 本理論が成立する条件

1. **両カメラが同一の雲台に剛体的に固定されている**
   → カメラ間の相対位置関係が雲台回転中に変化しない

2. **被写体が十分遠方にある（純回転近似が成立）**
   → ‖t‖/d が十分小さい（目安: 1% 以下、つまり d > 100·‖t‖）

3. **カメラのズームが固定されている**
   → K₁, K₂ が不変

4. **雲台の回転軸が既知で再現性がある**
   → 「pan 3°」と指示したら実際に 3° 回転する

5. **レンズ歪みが無視できる、または事前に補正済み**
   → 広角レンズの場合は歪み補正が必要

### 8.2 被写体が近い場合の対処

被写体が近い場合（‖t‖/d が無視できない場合）、純回転近似の
誤差が大きくなる。対処法:

**方法A: 深度情報を利用した補正**

```
  H(θ, d) = K₂ · (R_pantilt · R_rel + R_pantilt · t · nᵀ / d) · K₁⁻¹
```

物体認識カメラが深度情報を出力する場合、被写体ごとに
d を変えて H を補正できる。

**方法B: 複数の深度帯でキャリブレーション**

近距離・中距離・遠距離の被写体でそれぞれキャリブレーションし、
深度に応じて使い分ける。

### 8.3 精度向上のための追加手法

1. **K₂ の fx, fy を独立に推定**
   → 正方ピクセル仮定を外し、fx ≠ fy を許容

2. **主点 (cx, cy) も推定**
   → 画像中心仮定を外す（キャリブレーション角度が4つ以上必要）

3. **レンズ歪み係数の推定**
   → 広角レンズの場合に有効

4. **雲台の回転軸のオフセット推定**
   → 回転軸がカメラの光学中心と一致しない場合の補正

これらは現在の実装の `_optimize_K2` を拡張することで対応可能。
ただし、パラメータが増えると過学習のリスクがあるため、
キャリブレーション点の数とのバランスが重要。
