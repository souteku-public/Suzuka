## 1. システム構成と目的

### 1.1 物理的な構成

```
              ┌──────────┐
              │  cam1    │  ← 認識カメラ（物体検出用）
              │ (認識用)  │     雲台に載っており pan/tilt で回転する
              └────┬─────┘
                   │
              ┌────┴─────┐
              │   雲台    │  ← pan/tilt 制御可能
              │ (PTU)    │
              └────┬─────┘
                   │  固定
              ┌────┴─────┐
              │  cam2    │  ← RGBカメラ（映像出力用）
              │ (RGB)    │     三脚に固定されており動かない
              └────┬─────┘
                   │
              ━━━━━┿━━━━━
                 三脚
```

**重要な点**:
- **cam1（認識カメラ）だけが雲台で回転する**
- **cam2（RGBカメラ）は固定されており動かない**

### 1.2 やりたいこと

```
cam1 で物体を検出 → cam2 の画像上のどこに対応するかを求める
```

cam1 の画像上のピクセル座標 p₁ を、cam2 の画像上のピクセル座標 p₂ に
変換する Homography 行列 H を求めたい:

```
  p₂ = H · p₁
```

**課題**: 雲台の角度が変わると cam1 の視野が変わるため、H も変化する。
すべての角度で4点キャリブレーションを行うのは現実的でないため、
**1回のキャリブレーションから任意の角度の H を解析的に計算**したい。

### 1.3 記号一覧

| 記号 | 意味 | 次元 |
|------|------|------|
| K₁ | cam1（認識カメラ）の内部パラメータ行列 | 3×3 |
| K₂ | cam2（RGBカメラ）の内部パラメータ行列 | 3×3 |
| R_rel | cam1 から cam2 への相対回転行列 | 3×3 |
| t | cam1 から cam2 への並進ベクトル | 3×1 |
| H_base | 基準角度でのキャリブレーション済み Homography | 3×3 |
| R_pantilt | 雲台の回転行列 | 3×3 |
| p₁ | cam1 上のピクセル座標（同次座標） | 3×1 |
| p₂ | cam2 上のピクセル座標（同次座標） | 3×1 |
| fx, fy | 焦点距離（ピクセル単位） | スカラー |
| cx, cy | 主点（画像中心座標） | スカラー |

## 2. ピンホールカメラモデル

### 2.1 3D点からピクセル座標への投影

3D空間の点 P = (X, Y, Z)ᵀ がカメラの画像上のどこに映るかは:

```
       ┌ u ┐       ┌ fx  0  cx ┐   ┌ X ┐
  s  · │ v │   =   │  0  fy cy │ · │ Y │
       └ 1 ┘       └  0   0  1 ┘   └ Z ┘

  s · p  =  K · P_cam
```

- **(u, v)**: ピクセル座標
- **s**: スケールファクター（奥行き Z に相当）
- **K**: 内部パラメータ行列（カメラ固有、動かしても変化しない）

### 2.2 内部パラメータ行列 K の意味

```
       ┌ fx   0  cx ┐
  K =  │  0  fy  cy │
       └  0   0   1 ┘
```

| パラメータ | 物理的意味 |
|-----------|-----------|
| fx, fy | 焦点距離をピクセル単位で表したもの。f(mm) × ピクセル密度(px/mm) |
| cx, cy | 光学軸が画像平面と交わる点。通常は画像の中心付近 |

### 2.3 K⁻¹ の意味（ピクセル → 3D視線方向）

K の逆行列 K⁻¹ はピクセル座標を「3D空間での視線方向」に変換する:

```
  K⁻¹ · p = K⁻¹ · (u, v, 1)ᵀ = 3D視線方向ベクトル
```

これは後の導出で頻繁に登場する重要な操作。

### 2.4 ワールド座標からカメラ座標への変換

ワールド座標系の点 P_w をカメラ座標系に変換するには:

```
  P_cam = R · P_w + t
```

- **R** (3×3): カメラの姿勢（回転行列）
- **t** (3×1): カメラの位置（並進ベクトル）

## 3. Homography の基礎

### 3.1 Homography とは

2つの画像間のピクセル座標の対応関係を表す 3×3 の射影変換行列:

```
  s · p₂ = H · p₁
```

実際の座標変換:

```
       H₁₁·u₁ + H₁₂·v₁ + H₁₃
  u₂ = ─────────────────────────
       H₃₁·u₁ + H₃₂·v₁ + H₃₃

       H₂₁·u₁ + H₂₂·v₁ + H₂₃
  v₂ = ─────────────────────────
       H₃₁·u₁ + H₃₂·v₁ + H₃₃
```

### 3.2 Homography が成立する条件

以下の**いずれか**が満たされれば Homography が定義できる:

#### 条件A: 被写体が平面上にある場合

```
  H = K₂ · (R + t · nᵀ / d) · K₁⁻¹
```

- n: 平面の法線ベクトル、d: カメラから平面までの距離

#### 条件B: 純回転のみの場合（並進 t ≈ 0）

```
  H = K₂ · R · K₁⁻¹
```

被写体が十分遠方にあれば t·nᵀ/d → 0 となり、条件B に帰着する。

### 3.3 本システムでの H_base

基準角度 (pan₀, tilt₀) で4点キャリブレーションにより求めた H_base は:

```
  H_base ≈ K₂ · R_rel · K₁⁻¹
```

ここで R_rel は cam1 から cam2 への相対回転行列。
**H_base には K₁, K₂, R_rel の情報がすべて含まれている。**

## 4. 雲台回転による Homography の変化（核心の導出）

### 4.1 雲台回転の数学的表現

**Y軸周りの回転（pan）**:
```
              ┌  cos α   0   sin α ┐
  R_y(α)  =  │    0     1     0   │
              └ -sin α   0   cos α ┘
```

**X軸周りの回転（tilt）**:
```
              ┌  1     0       0   ┐
  R_x(β)  =  │  0   cos β  -sin β │
              └  0   sin β   cos β ┘
```

**合成回転**（先に tilt → 次に pan）:
```
  R_pantilt(α, β) = R_y(α) · R_x(β)
```

### 4.2 核心: 「cam1 だけが回転する」場合の導出

#### ステップ1: 基準角度での関係

基準角度で、ワールド上のある点が:
- cam1 の画像上で p₁_base に映る
- cam2 の画像上で p₂ に映る

このとき:
```
  p₂ = H_base · p₁_base        ... (A)
```

#### ステップ2: cam1 が回転したとき、同じワールド点はどこに映るか

cam1 が R_pantilt だけ回転すると、**同じワールド上の点**が
cam1 の画像上で**別の位置**に映る。

遠方の被写体（方向ベクトルで近似可能）の場合:

```
  基準角度での cam1 の視線方向:   d_base = K₁⁻¹ · p₁_base
  回転後の cam1 の視線方向:       d_new  = R_pantilt · d_base
```

よって、回転後に cam1 で観測されるピクセル座標は:

```
  p₁_new = K₁ · R_pantilt · K₁⁻¹ · p₁_base        ... (B)
```

**（B）の直感的な意味**:

```
  K₁⁻¹ · p₁_base   : ピクセル座標 → 3D視線方向に変換
  R_pantilt · (...)  : 3D空間で視線を雲台の回転ぶんだけ回す
  K₁ · (...)         : 3D視線方向 → ピクセル座標に戻す
```

#### ステップ3: p₁_base を p₁_new で表す

（B）を p₁_base について解く:

```
  p₁_base = (K₁ · R_pantilt · K₁⁻¹)⁻¹ · p₁_new
           = K₁ · R_pantiltᵀ · K₁⁻¹ · p₁_new      ... (C)
```

R_pantiltᵀ = R_pantilt⁻¹ （回転行列の逆 = 転置）

#### ステップ4: cam2 は固定なので p₂ は変わらない

cam2 は動かないので、同じワールド上の点は cam2 上で常に同じ位置に映る。

（A）に（C）を代入:

```
  p₂ = H_base · p₁_base
     = H_base · K₁ · R_pantiltᵀ · K₁⁻¹ · p₁_new
```

#### ステップ5: 最終公式

p₁_new を改めて p₁ と書くと:

```
┌────────────────────────────────────────────────────────────────────┐
│                                                                    │
│  H(Δpan, Δtilt) = H_base · K₁ · R_pantiltᵀ · K₁⁻¹               │
│                                                                    │
│  ここで:                                                           │
│    R_pantiltᵀ = (R_y(Δpan) · R_x(Δtilt))ᵀ                        │
│              = R_x(Δtilt)ᵀ · R_y(Δpan)ᵀ                          │
│              = R_x(-Δtilt) · R_y(-Δpan)                           │
│                                                                    │
│    Δpan  = pan  - pan₀   （基準角度からの変化量）                    │
│    Δtilt = tilt - tilt₀                                            │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

### 4.3 公式の直感的な理解

```
  H(Δpan, Δtilt) = H_base · K₁ · R_pantiltᵀ · K₁⁻¹
                    ─┬────   ──────────┬──────────
                     │                 │
                     │                 └─ 「cam1の回転を打ち消す」変換
                     │                    cam1上のピクセル座標を
                     │                    基準角度の座標に戻す
                     │
                     └─ 基準角度での cam1→cam2 の変換

  全体の流れ:
  ┌──────────────────────────────────────────────────────────────┐
  │                                                              │
  │  cam1の現在のピクセル                                         │
  │    ↓  K₁⁻¹                                                  │
  │  3D視線方向                                                   │
  │    ↓  R_pantiltᵀ（逆回転: 雲台の回転を打ち消す）              │
  │  基準角度での3D視線方向                                       │
  │    ↓  K₁                                                     │
  │  基準角度での cam1 ピクセル座標                                │
  │    ↓  H_base                                                 │
  │  cam2（固定）のピクセル座標                                    │
  │                                                              │
  └──────────────────────────────────────────────────────────────┘
```

### 4.4 なぜ「逆回転」になるのか

cam1 が**右**に pan すると、cam1 の画像上の物体は**左**に動く。

```
  カメラが右を向く → 世界が左にずれて見える
```

よって、cam1 上のピクセル座標を基準角度に戻すには、
カメラの回転と**逆方向**に回す必要がある → R_pantiltᵀ（転置 = 逆回転）。

### 4.5 具体的な計算例

cam1 の内部パラメータ（例）:

```
       ┌ 500    0   320 ┐
  K₁ = │   0  500   240 │   （640×480、焦点距離 500px）
       └   0    0     1 ┘
```

雲台が pan = +5° に回転した場合 (Δpan = 5°, Δtilt = 0°):

```
  R_y(5°) = ┌  0.9962   0   0.0872 ┐
             │    0      1     0    │
             └ -0.0872   0   0.9962 ┘

  R_y(5°)ᵀ = R_y(-5°) = ┌  0.9962   0  -0.0872 ┐
                          │    0      1     0    │
                          └  0.0872   0   0.9962 ┘
```

cam1 上のピクセルシフト量:
```
  500 × sin(5°) ≈ 43.6 ピクセル（水平方向）
```

cam1 の画像上で物体が左に 43.6px ずれたように見える。
この分を K₁ · R_pantiltᵀ · K₁⁻¹ が補正する。

### 4.6 もし構成が逆（cam2 が雲台上）だった場合との比較

| | cam1 が回転（本システム） | cam2 が回転（仮定） |
|---|---|---|
| **公式** | H_base · **K₁** · Rᵀ · **K₁⁻¹** | **K₂** · R · **K₂⁻¹** · H_base |
| **補正の位置** | H_base の**右**から掛ける | H_base の**左**から掛ける |
| **使う K** | **K₁**（回転するカメラ） | **K₂**（回転するカメラ） |
| **回転の向き** | **逆回転** Rᵀ | **順回転** R |

**法則: 回転するカメラの K を使い、そのカメラ側から補正を掛ける。**

## 5. K₁ の推定方法

### 5.1 なぜ K₁ の推定が必要か

公式 H(Δθ) = H_base · K₁ · R(Δθ)ᵀ · K₁⁻¹ を使うには
K₁ が必要だが、通常は未知である。

しかし、**基準角度とは異なる角度でもう1回キャリブレーションすれば
K₁ を逆算できる。**

### 5.2 推定の原理

角度 θ₁ でのキャリブレーション結果 H₁ が得られているとする。

```
  H₁ = H_base · K₁ · R(Δθ₁)ᵀ · K₁⁻¹
```

- R(Δθ₁) は既知（雲台の角度から計算可能）
- H_base と H₁ は実測値（4点キャリブレーションから）
- **未知数は K₁ のみ**

正方ピクセル仮定 (fx = fy) かつ主点を画像中心と仮定すると:

```
       ┌ fx   0   W₁/2 ┐
  K₁ = │  0  fx   H₁/2 │    （未知数は fx の1つだけ）
       └  0   0     1   ┘
```

### 5.3 推定アルゴリズム

```
  1. fx の候補値を設定
  2. K₁(fx) を構成
  3. 各キャリブレーション角度 θᵢ に対して:
     a. H_predicted = H_base · K₁ · R(Δθᵢ)ᵀ · K₁⁻¹ を計算
     b. 実測の対応点 (pts1, pts2) に対して再投影誤差を計算:
        error = Σ ‖ H_predicted · pts1ⱼ - pts2ⱼ ‖²
  4. 誤差が最小になる fx を採用
```

探索は2段階:
- **粗い探索**: fx を 0.3W₁ 〜 2.0W₁ の範囲で50点サンプリング
- **細かい探索**: 粗い探索の最良値の ±10% を100点サンプリング

### 5.4 キャリブレーション角度の数と精度

| キャリブレーション角度数 | K₁ 推定精度 | 備考 |
|---|---|---|
| 1 (基準のみ) | 推定不可 | 方程式が足りない |
| 2 (基準 + 1角度) | 推定可能 | 1軸の回転情報のみ |
| 3+ (基準 + 複数角度) | 良好 | 冗長な拘束条件で精度向上 |

### 5.5 なぜ K₁ であって K₂ ではないのか

```
  H(Δθ) = H_base · K₁ · R(Δθ)ᵀ · K₁⁻¹
                    ───              ────
                     ↑                ↑
                   この2箇所に K₁ が登場

  K₂ は H_base の中に含まれているが、公式上は独立に必要ない
```

K₁ は「cam1 のピクセル座標 ↔ 3D視線方向」の変換に使われる。
cam1 が回転するので、cam1 のピクセル空間で回転を補正する必要がある。
**回転するカメラの K が必要**。

## 6. 精度の理論的分析

### 6.1 誤差の分類

#### 誤差源1: 純回転近似の誤差

cam1 と cam2 の光学中心の距離を ‖t‖ とすると:

```
  H_true    = K₂ · (R + t·nᵀ/d) · K₁⁻¹
  H_approx  = K₂ · R · K₁⁻¹

  相対誤差 ≈ ‖t‖ / d
```

| cam1-cam2 間距離 ‖t‖ | 被写体距離 d | 相対誤差 |
|---|---|---|
| 50mm | 2m | 2.5% |
| 50mm | 5m | 1.0% |
| 50mm | 10m | 0.5% |
| 50mm | 50m | 0.1% |

本構成（cam2 の上に雲台 + cam1）では ‖t‖ は雲台の高さ + カメラの
取り付け距離に相当。通常 100〜200mm 程度。

#### 誤差源2: K₁ の推定誤差

K₁ の推定誤差 δfx があると:

```
  ピクセル誤差 ≈ δfx · sin(Δθ)
```

角度変化が小さいほど誤差は小さい。

#### 誤差源3: H_base の推定誤差

4点の指定精度に依存。すべての角度に均等に影響する。
4点を画像の広い範囲に分散配置することで緩和できる。

### 6.2 CG 描画精度への影響

1920×1080 の RGB カメラにおける誤差の意味:

| 誤差 (px) | 画面比率 | 視認性 | 判定 |
|---|---|---|---|
| 0.05 px | 0.003% | 認識不可能 | 問題なし |
| 0.5 px | 0.026% | サブピクセル | 問題なし |
| 1 px | 0.052% | 境界で微かに見える | ほぼ問題なし |
| 5 px | 0.26% | はっきり見える | 要改善 |
| 20 px | 1.04% | 明らかにずれている | CG合成不可 |

## 7. IDW 補間が失敗する数学的理由

### 7.1 射影変換群 PGL(3) の非線形性

Homography は射影変換群 PGL(3) に属する。この群は:

- **リー群**であり、ユークリッド空間ではない
- 行列の線形結合は群の元とは限らない
- 「2つの Homography の平均」は数学的に意味をなさない

具体例:

```
  H₁ = ┌ 1  0  0 ┐    H₂ = ┌ 0 -1  0 ┐
       │ 0  1  0 │         │ 1  0  0 │   （90°回転）
       └ 0  0  1 ┘         └ 0  0  1 ┘

  (H₁ + H₂) / 2 = ┌ 0.5 -0.5  0 ┐
                    │ 0.5  0.5  0 │   ← det = 0.5 ≠ 1
                    └  0    0   1 ┘       45°回転 + 縮小（！）
```

平均すると **回転だけでなくスケール変化が混入** する。
これが IDW 補間の根本的な問題。

### 7.2 対角方向で誤差が特に大きい理由

pan=3°, tilt=3° のような対角方向では:

```
  R_true = R_y(3°) · R_x(3°)    ← 2軸の合成回転（非可換）
```

**回転の非可換性** (R_y · R_x ≠ R_x · R_y) により、
IDW の重み付き線形和では原理的に正しい補間ができない。

## 8. 前提条件と限界

### 8.1 本理論が成立する条件

1. **cam1 が雲台に剛体的に固定されている**
   → cam1 と雲台の相対位置関係が回転中に変化しない

2. **cam2 が固定されている**
   → cam2 は振動等で動かない

3. **被写体が十分遠方にある（純回転近似が成立）**
   → ‖t‖/d が十分小さい（目安: d > 100·‖t‖）

4. **カメラのズームが固定されている**
   → K₁, K₂ が不変

5. **雲台の回転角度が正確**
   → 指示角度と実際の回転角度が一致する

6. **レンズ歪みが無視できる、または事前に補正済み**

### 8.2 被写体が近い場合の対処

被写体が近い場合（‖t‖/d が無視できない場合）:

**方法A: 深度情報を利用した補正**

物体認識カメラが深度情報を出力する場合、被写体ごとに
距離 d を考慮して H を補正できる。

**方法B: 複数の深度帯でキャリブレーション**

### 8.3 精度向上のための追加手法

1. **K₁ の fx, fy を独立に推定** → 正方ピクセル仮定を外す
2. **主点 (cx, cy) も推定** → キャリブレーション角度が4つ以上必要
